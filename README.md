# Travel Clock ESP32

Travel Clock ESP32 是参考工程 [GVIEW-Engine](https://github.com/zhengjunlang-bit/GVIEW-Engine) 中 GVIEW Travel 2.5 的独立微雪版本，适用于 ESP32-S3-Touch-LCD-1.54。`main/` 包含页面、图片资源、触摸、电池和音频代码；`components/` 包含该板使用的 GVIEW、LCD 与 SPI 源码。本目录不依赖仓库根目录的公共组件或 `examples/` 中的工程。

## 硬件

- ESP32-S3、16 MB Flash、8 MB PSRAM
- 240×240 ST7789 屏幕、CST816 触摸、ES8311 音频
- LCD：GPIO38/39/21/45/40/46；触摸：GPIO41/42，复位 GPIO47；音频：GPIO8/9/10/12，功放 GPIO7；电池采样：GPIO1、GPIO2

界面统一使用 320×240 内部画布，LCD 显示中央 240×240 区域（逻辑 x=40～279）。所有页面按 1:1 像素传输，普通图片、动画和 UI 图标不再随屏幕二次缩放。商店动画按所有帧的范围居中，设置菜单保留右侧半圆旋转布局，圆心在屏幕右侧之外，原始图标按 1:1 像素显示；花园使用原版风格的 224×98 三色草地资源，完整轮廓和实心绿色中心按 1:1 像素绘制，草地底图带稀疏的浅绿色细草纹，无黑影，植物保持资源原尺寸并以根部落在草地内。普通界面文字统一使用 16×16 汉字、8×16 英文数字的原生像素字形；首页时间保留较大的 22 像素高的点阵字形，天气卡片文字也按 LCD 实际像素绘制。

屏幕没有额外虚拟按键栏，触摸可在全屏使用。首页、日历、纯数字时钟、天气通过左右滑动循环切换；这四个主画面中，左侧实体 BOOT 短按进入商店，右侧实体 PLUS 短按进入花园，长按 BOOT 返回上一个主画面，长按 PLUS 进入下一个主画面。轻点屏幕左右侧不切页。连接电脑 USB 时，接入后的 2 秒内忽略 BOOT 输入；检测到按键释放后恢复正常操作，避免插线时误触发商店。主界面短按 PWR 不执行操作；长按约 1.5 秒打开“设置 / 关机 / 返回主界面 / 首页音乐：开或关”操作菜单。短按左右键选项、中键确认；切换首页音乐时会记住当前曲目，重新开启后恢复。设置首页保留左侧名称条、右侧半圆图标旋转布局，底部显示“长按左键退出”。子页顶部显示三等分的圆角按键提示，每格 80 像素、总高 24 像素；左侧按钮使用原版青绿色（RGB565 `0x0635`），右侧使用原版橙色（`0xFCC0`），中间 PWR 使用蓝灰色（`0x3B50`），三格统一使用白色文字。顶部触摸区域按 80／80／80 像素划分。顶部三格分别对应左键、PWR、右键的短按操作，触摸每格执行同一个操作。左右键遵循短按优先：某侧没有可用的短按动作时，自动由短按执行该侧可用的返回、刷新、保存或切换等功能，并更新顶部文字；该侧重复的长按提示隐藏。只有短按已用于翻项或调整时，额外功能才继续以长按提示放在底部。当前短按和长按均无可用动作时保留按钮底框并隐藏文字，例如扫描中的右键、密码为空时的删除、物品已使用时的确认等；操作恢复可用后自动显示。空白按钮区域不会触发其他按钮。有项目的选择列表使用上一项／下一项首尾循环，返回和设置仍使用各自的长按操作。

首页电量百分比每分钟更新一次；首次取得有效电池采样及重新进入首页时立即更新。

省电策略：音频停止后约 2 秒关闭采样计时器、音频解码器和功放，播放时再开启；首页音乐音量设为 0 时停止 MP3 解码。静态页面画面与上一帧相同时跳过 SPI 传输；屏幕亮度不随无操作时间改变，渲染帧率也不因亮度降低而改变。亮度按五组每日定时值切换，默认 07:00 为 4 档、09:00 为 8 档、17:00 为 6 档、19:00 为 4 档、23:00 为 2 档；已有自定义定时值保持不变。电池 ADC 每 10 秒采样一次。


声音设置子页用 BOOT / PLUS 选上一项／下一项，PWR 编辑当前项；编辑时 BOOT / PLUS 减小／增大，PWR 完成。音量每次调整 5%，范围为 0～100%；已有的非 5% 倍数音量会沿调整方向进入下一个 5% 档位。“首页音乐”按 PWR 进入 10 首 MP3 与静音的选择列表；列表中长按右键试听或停止当前曲目，短按中键选用，翻项或离开列表时停止试听。静音项和音量为 0 时不提供试听，闹钟等铃声优先播放。声音设置包含音量和首页音乐；计时器铃声及循环次数在计时器页面设置，番茄钟与闹钟的铃声选项仍在各自页面。系统设置保留温度补偿与版本信息。长按 BOOT 保存并返回，修改后停止操作约 2 秒也会自动保存。
选择亮度设置后直接进入五组定时亮度，长按 BOOT 保存并返回设置菜单。闹钟和定时亮度页使用 BOOT / PLUS 前后选择、编辑时减小 / 增大，PWR 切换编辑项。闹钟列表五行各高 38 像素，选中背景覆盖完整行宽和时间／星期两行内容；编号及橙色底框在整行内垂直居中。定时亮度列表的编号、时间和亮度值统一在 32 像素高的行背景内垂直居中。Wi-Fi 输入页使用完整 240×240 像素布局，小写字母、大写字母、数字、符号分为四个分类；字母和符号以 8 列网格显示，数字使用 3 列网格，字符键全部放在屏幕内。密码区可显示最多 63 位密码及长度，底部固定“删除 / 空格 / 连接”。

设置页三键规则：短按 BOOT 选上一项或减小，短按 PLUS 选下一项或增大，短按 PWR 确认或切换编辑项；长按 BOOT 返回上一级，长按 PLUS 执行页眉右侧的辅助操作。系统、闹钟和定时亮度页长按 BOOT 时会保存修改。菜单中短按 PWR 进入所选子页。

设置子页、商店和花园在底部 20 像素区域显示灰色长按提示，按当前状态显示返回、刷新、保存、分类或启停等操作；左键长按提示距左边缘 4 像素，右键长按提示按实际文字宽度右对齐、距右边缘 4 像素；提示区不响应确认操作，正文预留对应空间。

设置子页顶部显示按键操作提示，浏览时左右键选项，中键进入或编辑；编辑时左右键调整，中键完成。闹钟和定时亮度等多字段页面用中键切换字段。Wi-Fi 扫描、城市选择和文字输入依照列表或网格布局操作。首页音乐只在首页循环播放，离开首页停止；闹钟和番茄钟响起时优先播放所选铃声。帮助页短按 PWR 返回设置菜单。

恢复出厂会重置个人设置、城市、定时亮度、闹钟与铃声选择，清除已保存的 Wi-Fi 和花园植物；内置 MP3 文件保留。

Wi-Fi 键盘短按 BOOT／PLUS 前后选择字符和底部操作，PWR 执行选中项；长按 PLUS 循环切换 `abc / ABC / 123 / 符号`，长按 BOOT 返回扫描页。触摸可直接选择分类、点按字符和底部操作，也可左右滑动键盘切换分类。字符集覆盖空格和全部 94 个非空格可打印 ASCII 字符；输入超过 63 位时保留已有内容。

商店短按 BOOT／PLUS 浏览物品，长按 PLUS 切换分类。锁定物品按实体 PWR 扣除对应金币并解锁，再按实体 PWR 使用；顶部按钮仍可点击解锁或使用；商店与花园商店按钮区域之外的轻点不触发购买或装备设置，滑动浏览仍可用。已拥有的物品不重复扣费，解锁和装备立即保存。商品名称及花园商店植物名称使用 16×16 原生像素字形。“手套”和“背包”分别绑定各自的名称、价格、拥有记录和装备索引。

伙伴按解锁价格从低到高排列，同价时保持固定顺序，“不跟随”置于首项。新增火稚鸡（150 金币）、水跃鱼（150）、蛇纹熊（300）、斗笠菇（500）和雷电兽（600），支持商店动画预览与首页陆地跟随。显示排序不改变存档编号，已有解锁和装备记录可继续使用；移动范围按伙伴宽度限制在可见区域内。新增动画的来源与作者见[素材说明](assets/pokemon_followers/README.md)。

花园短按 BOOT／PLUS 选择植物，PWR 收获，长按 PLUS 进入花园商店。花园未满 20 株时，设备运行期间每跨过一个 5 分钟时间段生成 1 株，同一时间段只生成一次；无需先进入花园，进入时会显示已生成的植物。未收获植物的位置、种类和数量保存在 NVS，普通重启与仅刷应用分区后会恢复；每次生成或收获都会更新保存，恢复出厂设置时清空。首页右下角温度文字左侧有 16×20 彩色像素幼苗提示，背景透明，以浅色外缘和深色内缘保持在深浅场景中的轮廓；有未收获植物时每秒闪烁，花园为空时隐藏。场景颜色仍每 10 分钟更新。计时器的分钟、秒分成两行显示；番茄钟将四个 60×90 原始数字缩至 48×72，以 `MM:SS` 在屏幕中央横排；冒号使用 14×46 图像，整行完整显示在屏幕内。番茄钟短按左键返回（运行中为停止），短按右键启动／暂停／继续；启动后保留顶部按键提示，中间键可手动显隐。计时器运行时短按左键返回、短按右键停止；停止后左右键继续调整分钟和秒，长按右键清零；清零后长按右键进入铃声及循环次数设置。帮助页短按 PWR 或长按 BOOT 返回。

## MP3 音频

首页音乐、闹钟、番茄钟和计时器的铃声共用 10 首 MP3。曲目包括真新镇、宝可梦中心、紫苑镇、训练家对战、若叶镇、自然公园、圆朱市、未白镇、113 号道路和凯那市，取自 [Pokémon Red](https://www.zophar.net/music/gameboy-gbs/pokemon-red)、[Pokémon Gold](https://www.zophar.net/music/gameboy-gbs/pokemon-gold) 和 [Pokémon Sapphire](https://www.zophar.net/music/gameboy-advance-gsf/pokemon-sapphire) 的音乐存档。默认首页曲目是未白镇。`tools/prepare_mp3.py` 下载并核验源文件，再编码为 12 kHz、单声道、40 kbps；`tools/pack_sound_data.py` 将 MP3 打包进 12 MB 的 `sounddata` 分区镜像。

MP3 保持原始 PCM 幅度，音量由 ES8311 控制。界面 0～100% 直接对应编解码器 0～100 档；0% 使用硬件静音，100% 对应默认音量曲线的 0 dB。播放中调节由音频任务应用，关闭编解码器后会记住音量并在下次播放时恢复。

```bash
python3 tools/prepare_mp3.py
python3 tools/pack_sound_data.py
```

固件和音频数据分开烧录。`idf.py flash` 烧录启动程序、分区表和应用；还需把 `build/sounddata.bin` 烧录到分区表指定的 `sounddata` 偏移（当前为 `0x312000`），否则音乐无法播放。

首页太阳、闪烁星星、商店角色预览及花园植物均限制在微雪屏幕的可见区域内；滚动的场景元素保留原有运动方式。
首页把地面、海面、骑行场景和云一起下移 70 像素，保留原版云贴近地面的相对位置；顶部时间、太阳和底部信息都处在 240×240 可视区域内。左上实时时间使用 18 号逻辑字、约 22 像素物理字形；时间与日期使用 6 像素左边距，太阳保持在右侧可视区域内。飞行宠物的初始位置与每次动画目标都同步下移 70 像素，保持原版宠物与人物的相对距离、横向活动范围和飞行节奏。人物和车轮连同服饰每 8 秒在中心左右各 24 像素往返一次，起步和转向时减速、中段加速；向前时人物踩踏与车轮随位移更新，后退时人物脚部保持静止姿势，车轮仍随倒退滚动，保持 1:1 像素显示。凌晨睡眠场景保留人物、帐篷与篝火。首页插画在白天和夜间均约每 20 分钟向左缓慢移动最多 4 像素再回原位；时间、日期、天气、电量、城市、温度和植物提示随顶部图层向左最多 3 像素、向下最多 2 像素。所有变化都在可视区域内，以减少长期静止画面造成的残影风险。睡眠时隐藏骑行图层。其他场景图案不在每帧插值放大，太阳保留原有光晕渐变。首页扩展画布使用完整像素索引，避免底部图案回绕到顶部。首页实际渲染仅覆盖 LCD 可见的 240×240 区域，减少森林场景里不可见树木的绘制工作。
森林原版素材保留作为顶部树冠的生成输入；`tools/pack_imagegen_forest.py` 将 `assets/forest_top/` 中的树冠打包为当前使用的图片资源。首页的云、房屋、草、海面等固定尺寸图片仍按现有坐标绘制。
首页恢复原有场景切换，森林按原来的随机条件出现；使用图片技能为 `treeF0`～`treeF3`、`senlinB` 生成顶部树冠；五张素材都保持原宽、高 240 像素，使用原来的 1 位／4 位索引格式与调色板。树冠两侧留出透明边缘，避免树木进入屏幕中央时出现平直的裁切线。各图从原图第 30 行起到树根的像素原样保留；顶部新增树冠与原图前 30 行在接缝处融合。编辑后的透明 PNG 在 `assets/forest_top/`，可运行 `python3 tools/pack_imagegen_forest.py` 重新生成 `*Top.h`。森林沿用原版横向起点、滚动速度和回环坐标；纵向按原图高度锚定，树根仍贴近下移 70 像素后的草地，新增树冠向屏幕顶部展开。屏幕画面先合成到独立缓冲区，再由 SPI 任务发送，渲染任务按 25 帧/秒的节拍唤醒；四棵前景树在进入森林场景前预解码，首页滚动位移按原版 20 帧/秒的每秒速度换算。当前使用顶部树冠素材，配置位于 `main/PAGE/HOME/home.c`。

森林性能诊断：原设置最高 20 帧/秒，森林绘制约 29 ms、画面准备约 8 ms、SPI 发送约 27 ms；启用树木预解码后绘制约 25～27 ms。把目标设为 30 帧/秒时实际约 24～25 帧/秒，因此正式目标设为 25 帧/秒。
显示诊断：ST7789 使用 240×240、RGB565、4 线 SPI；当前 SPI 模式为 0，实测时钟 40 MHz，森林整帧发送约 26～27 ms。板上 LCD 排线没有引出 TE 同步信号，因此移动画面仍可能出现扫描与写入相遇造成的撕裂。对照仓库原版 ESP32-C3 驱动，原版请求 80 MHz SPI、发送 320×170 像素，并把 ST7789 帧率寄存器 `C6` 设为 `0x01`（约 111 Hz）；本版发送 240×240 像素、使用 40 MHz SPI，也设置 `C6=0x01`。两版整帧数据量分别是 108800 和 115200 字节，实际差异主要来自 SPI 吞吐与面板时序，不取决于 CPU 性能。原版代码同样没有 TE 同步，不能据此认定它在所有运动场景都不会撕裂；仅改变 SPI 模式或图片资源无法保证消除撕裂。
日历页只显示年月、星期和日期，背景沿用原版色值 `0x9EBF`。
天气页并排显示两张 110×196 像素卡片，分别对应明天和后天；天气图标保持原始像素大小。较长天气说明分为两行，温度、湿度、星期均在卡片内。天气页通过 Open-Meteo 获取所选城市明天和后天的预报；首页右上保留天气图标，天气描述和温度使用日期同款字体放在左上日期下方，电量放在右下。首页晴天显示大太阳时仍显示描述，天气未知时隐藏描述。纯数字时钟在右下温度左侧显示同款天气描述。天气每 5 分钟刷新；网络不可用时天气页显示等待状态，不使用模拟数据。

首页温度使用较小的 12×12 摄氏度图标，与温度数字垂直对齐；纯数字时钟仍使用原有的 16×16 图标。
普通文字在 LCD 实际像素上绘制；启用原生文字渲染的页面在缓冲区分配或绘制失败时会直接报错，避免悄悄回退到旧画布字体。滚动列表按多行文字自动增加行高，长 Wi-Fi 名称和密码会换行。搜索 Wi-Fi 列表的单行项目高 28 像素，双行项目高 44 像素；选中框和滚动位置按每项实际高度调整。成功、失败、金币不足等提示逐行按 LCD 实际字形宽度居中，整段在屏幕中央显示；文字全程保持原生像素绘制并定时消失，避免透明度变化时退回旧字体。页面切换或重建顶部按钮前清除旧提示，避免旧提示对象指向新页面对象。
纯数字时钟把四张原始 60×90 数字图以最近邻采样缩为 48×72 像素，左右两组之间使用原始 14×46 像素冒号，并随秒闪烁。日期和天气图标放在顶部，Wi-Fi、地区、天气描述、天气温度和温度符号放在底部，图标按原像素绘制。

## 自行编译与刷机

### 1. 安装工具并获取源码

按[乐鑫 ESP-IDF 5.5.2 安装指南](https://docs.espressif.com/projects/esp-idf/en/v5.5.2/esp32s3/get-started/)安装 ESP32-S3 编译环境。Windows 请打开安装程序提供的 **ESP-IDF Command Prompt**；macOS / Linux 请在终端执行 `. /你的/esp-idf/目录/export.sh`。工程和 ESP-IDF 的路径不要包含空格。

首次获取工程时执行：

```bash
git clone https://github.com/bianlius/waveshare-travel-clock-esp32.git
cd waveshare-travel-clock-esp32
```

项目已在 `CMakeLists.txt` 中指定 `esp32s3`，并包含 `sdkconfig.defaults`、分区表和 10 首 MP3，无需另行下载音频。已有本地工程时直接在工程目录继续。

### 2. 编译应用和音频镜像

在已激活 ESP-IDF 5.5.2 的终端、工程根目录中执行：

```bash
python tools/pack_sound_data.py
idf.py -DGVIEW_UI_AUDIT=OFF build
```

成功后会得到 `build/bootloader/bootloader.bin`、`build/partition_table/partition-table.bin`、`build/travel_clock_esp32.bin` 和 `build/sounddata.bin`。其中音频镜像由仓库内的 MP3 打包生成；`idf.py build` 不会自动生成音频镜像。构建产物位于 `build/`，不纳入 Git。

### 3. 烧录到设备

用可传输数据的 USB 线连接微雪 ESP32-S3-Touch-LCD-1.54。将下列命令中的 `PORT` 换成实际串口：Windows 如 `COM3`，macOS 如 `/dev/cu.usbmodem...`，Linux 如 `/dev/ttyACM0`。`idf.py flash` 烧录启动程序、分区表和应用；再把音频镜像写入当前分区表的 `sounddata` 地址 `0x312000`：

```bash
idf.py -p PORT flash
python -m esptool --chip esp32s3 -p PORT write_flash 0x312000 build/sounddata.bin
idf.py -p PORT monitor
```

串口没有出现时，按住 **BOOT** 键接入 USB 后松开；刷完后重新上电。微雪的[官方刷机教程](https://docs.waveshare.com/ESP32-S3-Touch-LCD-1.54/Firmware-Flashing)也有串口、下载模式和 Flash Download Tool 的图示。上述分开烧录方式在分区表不变时保留原有设置和花园存档。

### 可选：制作供 Flash Download Tool 使用的单文件镜像

若要按微雪教程在 `0x0` 烧录一个文件，可在编译和音频打包完成后执行：

```bash
python -m esptool --chip esp32s3 merge_bin --output build/travel-clock-full.bin --flash_mode dio --flash_freq 80m --flash_size 16MB 0x0 build/bootloader/bootloader.bin 0x8000 build/partition_table/partition-table.bin 0x10000 build/travel_clock_esp32.bin 0x312000 build/sounddata.bin
```

在 Flash Download Tool 中选择 **ESP32-S3 / USB**、`build/travel-clock-full.bin` 和地址 **`0x0`**。单文件镜像会覆盖设置、Wi-Fi 信息及花园存档。微雪教程中的固件下载链接是其官方测试固件，本项目请使用自己编译生成的镜像。

天气预报使用 Open-Meteo 免费接口，无需配置密钥。天气数据来源：Open-Meteo（CC BY 4.0）；免费接口仅供非商业用途。

此前设备测试已覆盖屏幕、触摸、按键及 ES8311 音频播放；修改固件后请按实际设备重新验收。

## 设备帧图检查

启用 `GVIEW_UI_AUDIT` 后，固件自动遍历页面并通过串口导出最终 LCD 帧；诊断模式会禁止写入设置和 Wi-Fi 存储，使用内存中的演示数据。捕获脚本需要 Python 的 pyserial 和 Pillow。
