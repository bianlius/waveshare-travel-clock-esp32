# AI Passport 旅行时钟

FoloToy AI Passport 的独立 ESP32-C3 构建目标，与仓库根目录的微雪版共用当前
GVIEW 页面、原版人物、61 种宝可梦、商店、花园、闹钟、设置和网络代码。

本目录仅维护板级实现。共用应用、渲染器及统一源码清单见[目录约定](../README.zh_CN.md)。
微雪专用适配独立存放在 `ports/waveshare/`，两端不复制游戏页面，也不各自维护公共源码清单。

ST7789P3 屏幕通过硬件旋转使用 **320×240 横屏**。界面使用完整横向宽度，像素
素材和字体保持原始比例；顶部按键、状态图标、天气卡片及底部提示按横屏边界
布局。“屏幕方向”可切换两种横屏方向；本板没有 IMU 或触摸屏。

## 操作

以看清横屏画面时三颗按键的实际左／中／右位置为准，原竖屏按键名称不再决定动作。

| 实际位置 | 微雪版动作 | 横屏正向对应硬件键 | 横屏反向对应硬件键 |
| --- | --- | --- | --- |
| 最左键 | 左键 | UP | OK |
| 中间键 | 确认／中键 | DOWN | DOWN |
| 最右键 | 右键 | OK | UP |

切换屏幕方向时，两侧按键映射同步交换；中间键保持确认。翻转时已经按住的按键会
取消本次动作，松手后才接受新操作，避免旧长按或松手触发错误动作。默认实体顺序
依据[官方按键示意图](https://ai-passport.folotoy.cn/guides/getting-started/)，并结合设备主人
确认的“当前最右键执行确认”校正。

短按／长按沿用微雪版：左右浏览、中键确认；主画面短按左键进入商店、右键进入
花园，单击中键按“首页 → 日历 → 天气 → 首页”循环切换；长按两侧
按键不切换主画面。商店长按右键切换分类、长按左键返回。长按中键
打开“设置／返回主界面／首页音乐”操作菜单，其中不提供关机选项。两侧长按阈值为 650 毫秒、中键为 1.5 秒，松手不再触发短按。某侧短按为空时，
短按直接执行可用的长按动作，与顶部按键提示一致。

Wi-Fi 首页、扫描／已保存列表、网络详情、连接状态和密码键盘统一使用完整横屏
视口。内容保持统一边距，网络行、四种键盘、密码、字数和操作按钮各自对齐；
63 位密码分两行显示，字数另占一行。Wi-Fi 布局参数放在本设备的
`include/wifi_layout_profile.h`，微雪通过同名接口提供原有布局；网络状态、
键盘和按键操作仍共用一份实现。

日历、城市选择、声音／系统／亮度／闹钟
设置及商店使用本设备的 `include/page_layout_profile.h`，提示文字按当前宽度
换行。角色和计时工具的数字字模保持原生尺寸；224 像素的花园草地继续居中，以兼容已保存
的植物坐标。
天气页显示今天、明天、后天三列，温度、湿度和星期保持对齐。微雪仍为明天／
后天两列，两端使用同一份三日预报数据。

## 构建与预览

需要 **ESP-IDF 5.5.3**、ESP32-C3 工具链、C 编译器及安装 Pillow 的 Python。
音频打包需要 `ffmpeg` 或 `imageio-ffmpeg`，也可用 `FFMPEG` 指向已有程序。
若 IDF Python 没有 Pillow，可用 `PYTHON_FOR_HOST` 指定主机 Python。无需修改
全局终端配置。激活 IDF 后，在本目录执行：

```bash
./tools/validate.sh             # 完整门禁
./tools/validate.sh --static    # 主机检查
./tools/validate.sh --firmware  # 隔离构建、验证及归档
```

本目标有独立默认配置和依赖锁。应用使用 16 行、10 KB 的 RGB565 渲染缓冲区，
另配 10 KB DMA 暂存区，文字直接绘入缓冲区，对象池为 256 项。每帧只整理一次有界
场景列表，数字和动画变换只计算一次；后续分条跳过不相交的图片和矩形。绘制下一条
时，DMA 可继续传输上一条；确认完成后才复用暂存区，每帧结束（包括局部刷新）均等待
最后一次传输完成。四种森林素材仅缓存每行有效范围和调色板，总量限制为 4 KB。
仅将像素解包循环放入 IRAM，Wi-Fi／PHY 的可选 IRAM 加速仍关闭。不分配全屏文字
缓冲／RGB565 双缓冲、完整森林解码图、PSRAM 或 LVGL。
电量来自 CW2017，失败时显示不可用。十首完整音乐重新打包为 12 kHz 单声道、
16 kbit/s MP3，原音频输入保持原样。Passport 使用固定版本的 Apache-2.0 microMP3/OpenCore
整数解码器，避免 minimp3 在 C3 上的软件浮点运算。此次更换解码器不改变音频文件、
采样率或码率，微雪版继续使用原解码器。BSP 采用仅播放模式，不分配未使用的麦克风 RX DMA；天气响应使用按请求分配
的 8 KB 有界缓冲区。按键回调仅入队，音频任务独占解码及写入。音频栈为 24 KB，门禁使用 C3 编译器的栈报告
核对解码器及任务开销，并额外保留 4 KB 余量。

每五秒输出一次 `travel_perf`，记录实际帧率、平均／最慢帧更新耗时、每帧剩余 DMA
等待、对象查找和绘制次数、空闲堆与最大连续块，以及音乐编号、音量、解码累计／峰值
耗时和音频任务剩余栈。目标为 25 FPS（每帧 40 毫秒）。
需在真机上覆盖首页动画、音乐、天气及 Wi-Fi/TLS；主机耗时和启动成功不代表实机
帧率达标。主机门禁还检查不同数字、嵌套／遮罩对象，以及 120 次延迟 DMA 的缓冲区
所有权和局部刷新结束等待。

macOS 可双击 [Run Passport Simulator.command](Run%20Passport%20Simulator.command)，
或在仓库根目录执行 `python3 ports/desktop/build.py --passport`。应用及存档独立，
不覆盖微雪模拟器；预览共用设备按键分发器和分条渲染器。主机检查逐像素比较
320×240 完整帧／分条截图，覆盖九个商店分类、七种天气、满额 30 株植物的
花园、18 种 Wi-Fi 状态及工具页面；另检查列表滚动、键盘操作、长名称／密码和
宽度超过 255 像素的圆角底图。
另有页面状态检查目标视口、表单、日历／城市列宽、闹钟和提示换行；源码
检查防止共用页面重新写死方形视口。微雪继续使用独立的方形布局参数。

## 固件与存档

门禁保留 `build/FoloToy-AI-Passport-full.bin`、匹配的 ELF／MAP、应用、引导程序、
分区表、音乐及 `flash_args`。可校验的归档在 `build/firmware/<完整固件SHA256>/`，
`manifest.json` 记录匹配的构建文件。

```bash
python tools/archive_firmware.py verify build/firmware/<完整固件SHA256>
```

| 分区 | 地址 | 大小 |
| --- | --- | --- |
| NVS／PHY | `0x9000`／`0xF000` | `0x6000`／`0x1000` |
| 应用 | `0x10000` | `0x300000` |
| 游戏／Wi-Fi | `0x310000`／`0x311000` | 各 `0x1000` |
| 受保护 `cardid` | `0x356000` | `0x4000` |
| 音乐 | `0x35A000` | `0x4A6000` |

门禁验证分区 MD5、边界、3 MB 应用上限、受保护身份、全部音轨、合并数据及 ELF。
音乐分区位于 `cardid` 之后，**已有身份的 Passport 不应直接写入整个合并镜像**，
否则填充会擦除身份。应按 `flash_args` 地址写入已验证的分段镜像，其中不包含
身份、NVS 或存档。后续分区兼容的更新可仅在 `0x10000` 写应用以保留数据。
应用单文件不能写到 `0x0`，已有身份的设备不能整片擦除。

构建不会自动刷机。屏幕实际方向／颜色、ADC 阈值、声音、联网内存压力、帧率、
休眠唤醒及数据保留，仍需真机验收。
